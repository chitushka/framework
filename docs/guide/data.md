# Данные

## Connection и dialect

`db.Connection` оборачивает `database/sql`, настраивает pool и выбирает dialect. Создавайте одно соединение на базу как singleton и закрывайте его в shutdown модуля. Всегда передавайте context с deadline.

## Query Builder

Builder отделяет SQL identifiers от значений и формирует placeholders dialect-а. Значения передавайте аргументами; не собирайте SQL из пользовательских строк. Динамические имена колонок выбирайте из allowlist.

## Транзакции

Внешний `Transaction` начинает SQL-транзакцию, вложенный создаёт savepoint. Ошибка внутреннего callback откатывает его savepoint; panic также приводит к rollback и затем продолжает распространяться. Границу транзакции размещайте в application service, который знает полный бизнес-сценарий.

Не выполняйте сетевые вызовы внутри долгой транзакции. Для надёжной публикации событий после commit используйте outbox-паттерн.

## Миграции

Миграции имеют возрастающую версию и пары up/down. CLI использует advisory lock, поэтому параллельный запуск не применяет одну миграцию дважды. Перед production проверяйте миграции на копии данных и отдельно оценивайте блокировки DDL.

## Active Record

Active Record подходит для CRUD и административных экранов. Metadata задаёт table, primary key, поля и optimistic lock. Relations загружаются явно, чтобы избежать скрытого N+1.

Для сложной доменной логики используйте отдельные модели и repository: Active Record не должен становиться обязательной границей всей системы.
