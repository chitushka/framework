# Приложение и модули

## Composition root и DI

Контейнер поддерживает constructors, singleton, transient и привязку интерфейса. Регистрируйте зависимости до запуска приложения и проверяйте каждую ошибку регистрации. Не используйте контейнер как service locator внутри бизнес-кода: зависимости должны быть видны в аргументах конструктора или action.

```go
container := di.New()
if err := container.Provide(NewRepository, di.Singleton()); err != nil {
    return err
}
if err := container.Provide(NewService); err != nil {
    return err
}
```

Singleton подходит для concurrency-safe клиентов и пулов. Transient — для объектов с кратким локальным состоянием. Request-scoped состояние передаётся через `context.Context`, `web.Context`, session и аргументы action.

## Модули

Модуль реализует четыре метода:

- `ID` возвращает стабильное уникальное имя;
- `Register` добавляет зависимости и компоненты;
- `Boot` запускает фоновые процессы;
- `Shutdown` останавливает их.

Сначала регистрируются все модули, затем они запускаются в порядке добавления. При ошибке уже запущенные модули останавливаются в обратном порядке. После успешного запуска runtime-ошибка модуля через `ErrorSource` завершает всё приложение.

## Components и events

`component.Registry` полезен для именованных инфраструктурных объектов, например нескольких соединений с БД. Для обычной бизнес-зависимости предпочтительнее типизированный constructor DI.

Event Bus предназначен для реакции нескольких независимых подписчиков на доменное или инфраструктурное событие. Последовательная публикация сохраняет порядок и останавливается на ошибке; конкурентная подходит независимым обработчикам. Не используйте события там, где вызывающему коду нужен непосредственный результат.

## Behaviors

Behavior — типобезопасный decorator именованного компонента. Цепочка собирается явно, проверяет циклы и сохраняет интерфейс декорируемого сервиса. Типичные применения: аудит, метрики, retry и кэширование.
