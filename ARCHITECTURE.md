# Архитектура Chitu Framework

## Принципы

- Реализация следует идиоматическому Go: явные зависимости и ошибки, небольшие интерфейсы на стороне потребителя, композиция вместо наследования и минимально необходимая рефлексия.
- Yii2 служит архитектурной и DX-основой: из него заимствуются проверенные границы компонентов, жизненный цикл, модули, события, behaviors, Active Record, URL Manager и подходы Console/Gii. PHP-идиомы и динамическая магия Yii2 не переносятся буквально, если они противоречат модели Go.
- Ядро использует только стандартную библиотеку Go.
- Компоненты зависят от малых интерфейсов; конкретные реализации связываются в точке сборки.
- Неявная магия ограничена проверяемой рефлексией DI-контейнера.
- Запуск и остановка имеют явный порядок, принимают `context.Context` и возвращают ошибки.
- Пакеты верхнего уровня не импортируются ядром, поэтому web, db, cache и прочие подсистемы можно использовать независимо.

## Имена пакетов

Имена `app`, `di`, `event` и `web` оставлены намеренно: они короткие, строчные, однословные и не повторяют module path. `di` является устоявшимся техническим сокращением. Пакеты именуются по предоставляемой области ответственности, а не по отдельному типу или слою Yii2.

## Текущие компоненты

```text
Application
  ├── DI Container
  ├── Event Bus
  ├── Config Loader
  └── Modules (register → boot → shutdown)
```

### `di`

Контейнер хранит определения по `reflect.Type`. Зависимости создаются конструкторами либо автоматической сборкой указателей на структуры. Поля для автоматического внедрения помечаются `di:"inject"`. Интерфейс связывается с реализацией явно. Singleton создаётся через `sync.Once`; циклы зависимостей обнаруживаются до вызова конструктора.

### `event`

Локальная типизированная по имени шина событий. Обработчики имеют приоритет и стабильный порядок регистрации. Последовательная публикация подходит для lifecycle hooks, конкурентная — для независимых обработчиков. Ошибки объединяются через `errors.Join`.

### `app`

`Application` владеет контейнером, шиной и модулями. Регистрация всех модулей выполняется до их запуска. При ошибке `Boot` уже запущенные модули останавливаются в обратном порядке. Обычная остановка также идёт в обратном порядке.

### `web`

HTTP-слой построен поверх `net/http`: `Router` реализует `http.Handler`, а framework handler возвращает ошибку вместо самостоятельной отправки аварийного ответа. `Context` хранит request/response и параметры маршрута. Middleware являются обычными функциями-декораторами. Маршруты регистрируются до начала обслуживания запросов, после чего чтение таблицы маршрутов безопасно конкурентно.

### `config`

Загрузчик заполняет пользовательские Go-структуры и не вводит глобальное хранилище. JSON-файлы накладываются в порядке объявления, затем применяются `.env`-файлы и окружение процесса. Поля связываются явно тегами `env`, `envDefault`, `envRequired`; поддерживаются скалярные типы, duration, slices, pointers и `encoding.TextUnmarshaler`. Такой API сохраняет типобезопасность и позволяет зарегистрировать готовую конфигурацию в DI как обычный singleton.

## Правила дальнейшего развития

1. При конфликте между буквальным повторением API Yii2 и идиоматическим Go выбирается идиоматический Go с сохранением назначения и удобства исходного механизма.
2. `web`, `db`, `cache`, `queue`, `session`, `auth` могут зависеть от `di` и `event`, но не друг от друга без интерфейса.
3. Интеграции с Redis, RabbitMQ и конкретными SQL-драйверами размещаются в отдельных пакетах/модулях.
4. Публичные API получают unit-тесты одновременно с реализацией.
5. Обратная совместимость публичного API сохраняется после первого стабильного релиза.
